# wax 사용 매뉴얼

wax는 기능 하나를 **기획 → 설계 → 구현 → 검토 → 보고**로 나누어 진행하고, 문서와 완료 근거를 프로젝트에 남깁니다.

## 한 줄 요청으로 자동 진행 (0.12.0)

`init`은 기본값으로 바로 참여하고 대시보드를 엽니다. 새 요청에서 두 모드를 선택합니다.

| 모드 | 시작과 실행 |
| --- | --- |
| 프로젝트 | 목표를 입력하면 범위·작업 순서와 선행 관계·산출물·완료 기준을 담은 워크플로우를 먼저 작성합니다. 화면에서 확인하고 **이 워크플로우로 시작**을 눌러야 설계·구현·검토·보고로 진행합니다. 수정 요청은 워크플로우를 다시 작성하며 새 내용을 확인해야 시작합니다. |
| SM · 유지보수 | 오류·개선 요청을 접수·분석 → 영향 확인 → 수정 → 회귀 검증 → 처리 보고로 바로 처리합니다. 기획과 설계 문서는 요청 규모에 맞게 간결하게 남기고 실제 테스트 근거는 유지합니다. |

처음에는 프로젝트 모드가 선택되며 이후에는 프로젝트별 마지막 선택을 기억합니다. `init --mode sm` 또는 `init --mode project`로 첫 화면을 지정할 수도 있습니다(각 호스트 문법 사용). 모드는 요청을 만든 뒤 바뀌지 않습니다. 다른 모드로 진행하려면 새 요청을 만드세요. 모드 정보가 없는 기존 요청은 SM 흐름을 유지합니다. 두 모드 모두 선택한 CLI의 별도 세션이 실행하며 기존 터미널 AI에 자동 분산 배정하지 않습니다.

첫 화면의 시작 가이드는 실행 도구 선택 → 할 일 입력 → 진행과 보고 확인 순서를 안내합니다. 설치 여부를 확인하며 로그인 여부는 실제 실행에서 확인합니다. 도구 설치 후에는 **도구 다시 확인**을 누르세요.

새 요청의 실행 도구에서 Codex·Claude Code·Gemini CLI·GitHub Copilot CLI·Antigravity CLI 중 설치한 도구를 선택합니다. 해당 CLI의 로그인 또는 API 설정과 계정 사용량·비용·데이터 정책이 적용됩니다. 요청은 저장된 도구로 계속 진행하며 다른 도구를 쓰려면 새 요청을 만듭니다. Codex·Claude·Gemini·Copilot의 새 권한 요청은 화면에서 이번만 허용하거나 거부합니다. Antigravity는 기존에 허용된 범위로 실행하며, 새 권한 요청이 막히면 터미널의 설정을 확인해야 합니다. 기존 터미널 세션을 자동으로 깨우거나 다른 AI의 배정을 바꾸지는 않습니다. 자동 진행의 PM은 요청을 처리하는 역할이며, 기존 프로젝트 PM을 교체하지 않습니다.

- 질문이 생기면 채팅으로 답합니다. 진행 중 보낸 추가 지시는 현재 단계가 끝난 뒤 반영됩니다. 즉시 멈추려면 **중지**를 누릅니다.
- 중단·오류의 이유는 요청 위에 표시합니다. **이어서 진행**은 저장된 단계부터 재개합니다. 서버 재시작이나 페이지 조회만으로 AI를 재호출하지 않습니다.
- 요청은 프로젝트당 한 번에 하나씩 실행합니다. 구현·검토에는 실제 통과한 테스트 근거가 필요하며, 다른 세션이 단계를 수정하면 충돌을 보고합니다. 단계 실행의 제한 시간은 30분입니다.
- 기록은 `.wax/chat/requests/`, 단계 문서는 `docs/wax/<자동 생성 ID>/`에 저장합니다. 기존 작업·팀 배정은 **상세 기록**(`/manage`)에서 계속 관리합니다.
- 일반 팀 채널(`/chat`)은 대화 기록용입니다. 자동 진행은 첫 화면에서 **워크플로우 만들기**(프로젝트) 또는 **시작하기**(SM)로 요청합니다. 워크플로우 확인은 실행 권한 승인과 별개이며 기존 CLI 권한은 그대로 적용됩니다.


## 실행 승인

실행 중 콘솔에서 묻는 권한 요청을 대화창에서 처리하려면 [실행 승인 관리](./APPROVALS.md)를 참고하세요. 연결된 요청만 요청별 **이번만 허용 / 거부** 버튼으로 응답합니다.

## 작업 인수인계

새 세션에서 기존 작업을 이어받을 때는 먼저 다음 명령으로 인수인계 문맥을 읽으세요.

```sh
node /path/to/wax/bin/wax.mjs --project /path/to/my-app context login --budget 3000
```

`login`은 기존 작업 ID입니다. 목표, 현재 단계와 다음 행동, 화이트보드 결정과 답변·결정이 연결되지 않은 질문, 실행 근거, 개선 사유와 단계 문서 발췌를 보여 줍니다. 각 항목의 `.wax/features/<id>.json#/...` 또는 `.wax/chat/board/<id>.jsonl#<노트 ID>` 참조로 원본을 확인할 수 있습니다. 단계 스킬과 `work`에서도 작업 전에 이 명령을 읽도록 안내합니다.

`--budget`은 유니코드 문자 수이며 토큰 수가 아닙니다. 기본 3,000자, 범위 1,000~100,000자입니다. 끝의 표시/전체 개수와 `…`는 생략된 항목과 원문이 있음을 알려 줍니다. 출력은 규칙에 따른 발췌이므로 최신 `status`, 전체 단계 `prompt`와 필요한 원본도 확인하세요. 질문은 해당 작업 보드 범위이며, 답변이 연결돼도 실제 해결을 보장하지 않습니다. 손상된 보드 기록은 제외 개수를 표시하고, 안전하지 않은 저장 경로나 손상된 작업 파일은 오류로 알립니다.

조회는 읽기 전용이며 외부 AI를 호출하지 않습니다. 과거 주기의 테스트와 현재 주기의 테스트를 구분하고 실행 당시 커밋·작업 트리 상태를 표시합니다. 기록된 통과는 현재 코드의 통과를 보장하지 않으므로 변경 후에는 필요한 테스트를 다시 실행하세요. 보관·완료된 작업은 자동으로 재개하지 않습니다.

## 1. 무엇이 필요한가요?

Node.js 22 이상과 로그인된 Claude Code, Codex, GitHub Copilot CLI, Gemini CLI 또는 Antigravity CLI 중 하나가 필요합니다. wax는 공개 저장소 [cafein-network/wax](https://github.com/cafein-network/wax)에서 각 도구의 마켓플레이스로 바로 설치하거나, [wax 사이트](https://wax.me2shop.com/#download)에서 ZIP으로 내려받을 수 있습니다. 배포본에는 플러그인 소스·테스트·매뉴얼이 들어 있습니다. wax 코드에는 AGPL-3.0 라이선스(무료로 쓰고 고치고 배포할 수 있으며, 배포 시 소스 제공 조건 준수, 수정본을 네트워크로 제공하면 원격 사용자에게 대응 소스 제공)가 적용되며 AI 도구와 API의 사용 요금·한도는 별도입니다.

## 2. 코드 내려받기

ZIP을 **모두 압축 풀기**로 해제한 뒤 내부에 `package.json`과 `bin/wax.mjs`가 있는 `wax` 폴더를 찾습니다. `.claude-plugin` 숨김 폴더도 포함되어 있어야 합니다. 플러그인은 `npm install` 없이 실행됩니다.

Windows·WSL 예제와 업데이트 방법은 ZIP 안의 `INSTALL.md`를 참고하세요. 이 매뉴얼에서 `/path/to/wax`은 예시 경로입니다. 반드시 압축을 푼 실제 절대 경로로 바꾸세요.

아래 예제에서 `/path/to/my-app`은 **실제로 코딩할 프로젝트 디렉터리**로 바꾸세요. 해당 디렉터리는 먼저 존재해야 합니다. 플러그인 소스 디렉터리와 작업할 프로젝트를 구분하세요.

## 3. Claude Code에서 첫 작업 시작

작업할 프로젝트에서 wax 플러그인을 로드합니다. 이 방식은 해당 Claude 세션에 적용되므로 새 세션을 열 때 같은 옵션을 사용하세요.

```sh
cd /path/to/my-app
claude --plugin-dir "/path/to/wax"
```

다른 컴퓨터에서는 `--plugin-dir` 뒤의 경로도 실제 위치로 바꾸세요. npm 설치 없이 동작합니다.

매번 `--plugin-dir`을 붙이지 않으려면 한 번만 설치합니다: `claude plugin marketplace add "/path/to/wax"` 뒤 `claude plugin install wax@wax`. 압축을 푼 폴더가 그대로 마켓플레이스이며, Codex(`codex plugin marketplace add` → `codex plugin add wax@wax`)와 GitHub Copilot CLI(`copilot plugin marketplace add` → `copilot plugin install wax@wax`)도 같은 폴더로 한 번 설치합니다. 업데이트·제거는 설치 안내(INSTALL.md)의 "한 번 설치" 절을 보세요.

처음에는 Claude 대화창에서 시작 명령을 한 번 실행합니다.

```text
/wax:init
```

설정 질문 없이 기본 이름으로 바로 참여하고 대시보드를 엽니다. 작업은 진행 중인 것이 하나면 그 작업, 아니면 없음으로 정하며 기존 PM은 유지합니다. 이름·작업·PM 옵션을 명시하면 그대로 적용합니다. 끝나면 이 세션이 팀 채널에 참여해 가상 사무실에 캐릭터로 나타나고, 다른 AI 세션이 참여하는 방법(`/wax:join`)을 알려 줍니다. init과 join은 대기 상태로 참여하며, 실제 단계 작업을 시작할 때 작업 중으로 바뀝니다. 대시보드를 나중에 다시 열 때도 `/wax:init`을 실행합니다.

자동 진행은 대시보드 첫 화면에서 한 줄로 요청합니다. 터미널에서 각 단계를 직접 관리하려면 다음처럼 기능을 요청합니다.

```text
/wax:plan email-login 이메일과 비밀번호로 로그인하는 기능을 만들어줘
```

wax가 기존 코드를 확인하고 요구사항·범위·수용 기준을 정리합니다. 결정이 필요한 질문에 답한 뒤 결과를 확인하세요. 한 명령은 그 단계의 작업을 수행하며, 모든 후속 단계를 한꺼번에 실행하지 않습니다.

## 4. 단계를 차례로 진행

| 명령 | 하는 일 |
| --- | --- |
| `/wax:init` | 시작하기: 팀 채널 참여, 맡을 작업, 대시보드 열기, PM 지정을 한 번에 |
| `/wax:join` | 다른 AI 세션이 팀 채널에 참여(이름·작업만 정함) |
| `/wax:plan email-login …` | 새 기능의 문제·범위·수용 기준 정리 |
| `/wax:design email-login` | 구조·데이터·수정 파일·검증 방법 설계 |
| `/wax:implement email-login` | 호스트의 도구로 실제 코드 수정 및 관련 검사 실행 |
| `/wax:review email-login` | 설계와 실제 결과 비교, 테스트 근거와 미검증 항목 기록 |
| `/wax:report email-login` | 결과·검증·사용법·남은 과제 정리 |
| `/wax:status email-login` | 현재 단계와 완료 근거 확인 |
| `/wax:iterate email-login 만료 토큰 처리 개선` | 이전 주기를 보관하고 구현 단계로 돌아가기 |

예를 들어 첫 기획을 마친 후 다음 명령을 한 번씩 실행합니다.

```text
/wax:design email-login
/wax:implement email-login
/wax:review email-login
/wax:report email-login
```

현재 단계의 문서와 완료 근거가 있어야 다음 단계로 넘어갑니다. 검토는 확인된 통과 판정이 추가로 필요합니다. 해결되지 않은 문제나 미검증 기준이 남으면 검토를 완료하지 않고 그 이유를 알려줍니다. 실제로 실행하지 않은 테스트는 통과했다고 기록하면 안 됩니다.

검토에서 문제가 발견됐다면 다음과 같이 개선합니다.

```text
/wax:iterate email-login 만료된 인증 토큰을 거부하도록 개선
/wax:implement email-login
/wax:review email-login
/wax:report email-login
```

기능 ID는 영문 소문자·숫자로 시작하며 소문자·숫자·하이픈만 포함하는 1~64자입니다. `email-login`, `dashboard`, `payment-v2`처럼 정하세요.

## 5. Gemini CLI에서 사용

처음 한 번 확장을 연결합니다.

```sh
gemini extensions link "/path/to/wax"
cd /path/to/my-app
gemini
```

새 Gemini 세션에서 Claude와 같은 명령을 사용합니다. 처음에는 `/wax:init`으로 시작하고, 이어서 `/wax:plan`, `/wax:design` 등을 실행합니다. 확장 연결이나 명령 파일 변경 후에는 세션을 다시 시작하세요. 이 프로젝트에서 Gemini TOML 문법은 검사했지만 실제 Gemini 호스트 실행은 아직 검증하지 않았습니다.

설치 버전은 플러그인 폴더에서 `node bin/wax.mjs --version`으로 확인합니다.

## 5-1. Codex에서 사용

압축을 푼 원본 플러그인과 대상 프로젝트를 연결합니다. 원본은 계속 같은 위치에 두세요.

```sh
node "/path/to/wax/scripts/install-codex.mjs" --project "/path/to/my-app"
node "/path/to/wax/scripts/install-codex.mjs" --project "/path/to/my-app" --check
cd /path/to/my-app
codex
```

Codex의 `/skills`에서 13개 스킬을 확인하고 대화창에서 사용합니다. `$`는 스킬 호출, `@`는 파일 첨부입니다. 배정받은 일은 `$wax:work <업무ID>`로 실행하며, wax 팀 채널의 `@이름` 알림과 구분하세요. 다음 예시는 셸 터미널 명령이 아닙니다.

```text
$wax:init
$wax:plan email-login 이메일 로그인 구현
$wax:design email-login
$wax:implement email-login
$wax:review email-login
$wax:report email-login
$wax:status email-login
$wax:iterate email-login 만료 토큰 처리 개선
```

설치기는 프로젝트의 `.agents/skills/wax-*`에 원본 스킬을 연결합니다. 기존 다른 스킬이나 Codex 설정을 덮어쓰지 않으며 같은 설치를 반복해도 됩니다. Windows는 디렉터리 junction, Linux·WSL은 심볼릭 링크를 사용합니다. 원본 경로가 바뀌면 설치 확인이 실패하므로 기존 링크를 확인한 뒤 다시 연결하세요. 새 스킬이 보이지 않으면 Codex를 재시작합니다.

현재 단계의 문서·완료 근거와 `.wax/features` 기록은 다른 호스트와 공유합니다. Codex 자체의 로그인·도구 권한을 사용합니다.

## 5-2. Antigravity CLI에서 사용

Antigravity CLI(`agy`)는 프로젝트의 `.agents/skills`에서 스킬을 읽으므로 5-1절의 설치기를 그대로 사용합니다. Codex용으로 이미 연결했다면 추가 설치가 필요 없습니다.

```sh
node "/path/to/wax/scripts/install-codex.mjs" --project "/path/to/my-app" --check
cd /path/to/my-app
agy
```

새 세션의 `/skills`에서 13개 스킬을 확인합니다. Antigravity CLI는 스킬을 슬래시 명령으로 바꾸므로 `/plan email-login 이메일 로그인 구현`, `/design email-login`처럼 스킬 이름으로 호출합니다. 실제 표시 이름은 `/skills` 목록을 따르며, 이름이 겹치면 "wax plan 단계를 실행해줘"처럼 요청할 수 있습니다. 시작 명령 `/init`이 Antigravity CLI 자체 명령과 겹치면 "wax init 스킬로 시작해줘"처럼 요청하세요.

`agy plugin install`이나 `agy plugin import gemini`는 파일을 다른 위치로 복사·변환하므로 스킬이 함께 제공되는 CLI를 찾지 못할 수 있습니다. 프로젝트 연결 방식을 사용하세요. 실제 Antigravity CLI 세션 실행은 아직 검증하지 않았습니다.

## 5-3. GitHub Copilot CLI에서 사용

GitHub Copilot CLI(`copilot`)에는 한 번만 설치합니다. Microsoft Copilot이 아니라 GitHub Copilot 구독으로 쓰는 터미널 도구입니다. 압축을 푼 wax 폴더를 로컬 마켓플레이스로 등록하면 모든 프로젝트에서 wax 스킬을 씁니다.

```sh
copilot plugin marketplace add "/path/to/wax"
copilot plugin install wax@wax
```

로컬 마켓플레이스는 폴더를 복사하지 않고 바로 읽습니다. 새 버전은 같은 경로의 폴더 내용을 바꾸면 다음 세션부터 적용됩니다. 처음에는 "wax init 스킬로 시작해줘"로 시작합니다. 스킬은 "wax plan 스킬로 email-login 이메일 로그인 기획해줘", "wax design 스킬로 email-login 설계해줘"처럼 이름을 밝혀 요청합니다(`/status` 같은 GitHub Copilot CLI 자체 명령과 이름이 겹치기 때문). 팀 채널에서 세션 종류는 `copilot`, 기본 이름은 `copilot-<폴더 이름>`입니다.

프로젝트에 `.agents/skills`(5-1절)를 연결해 둔 경우에도 충돌하지 않습니다. 같은 이름의 스킬은 프로젝트 쪽이 우선하고 한 벌만 보입니다.

## 6. 팀 대시보드: AI 세션 협업과 일일 업무보고

대시보드는 어느 코딩 도구의 세션이든 한 화면에서 같은 방식으로 보여 줍니다. 팀 패널의 각 세션에는 **다음 명령**이 그 도구의 문법으로 나옵니다. 배정된 업무가 있으면 work, 없으면 맡은 작업의 현재 단계, 맡은 작업이 끝났으면 status이며, 복사 버튼으로 그 세션에 그대로 붙여 넣을 수 있습니다. 업무 배정 폼에서 담당 세션을 고르면 그 세션이 실행할 명령을 미리 보여 주고, 가상 사무실에서 캐릭터를 눌러도 같은 다음 명령이 나옵니다. 도움말(`/help`)의 "도구별로 부르는 방법" 표에 모든 명령이 정리되어 있습니다.

세션은 참여할 때 `wax chat join --model <모델>`로 자기 모델을 밝힐 수 있습니다(같은 도구에서도 모델을 바꿀 수 있기 때문). 대시보드와 인사기록 카드에 "도구 · 모델"로 표시되며, 세션이 스스로 밝힌 값입니다.

여러 코딩 도구 세션(Claude Code·Codex·Gemini CLI·Antigravity CLI·GitHub Copilot CLI)이 같은 프로젝트에서 일할 때, 각 세션의 AI가 **팀원**으로 참여합니다. 대화·업무 배정·일일 보고는 프로젝트의 `.wax/chat/`에 저장되고, 로컬 대시보드에서 실시간으로 확인합니다. 상세 기록과 팀 채널은 기록을 보여 줍니다. 첫 화면의 요청과 보고에서 사용자가 요청을 보내면 선택한 CLI의 별도 세션이 작업합니다. 가상 사무실의 안내 NPC(진행 소식을 전하는 제이크, 도움말·사무실을 안내하는 써니)는 프로젝트 기록과 현재 시각으로 말합니다. 리나의 도구 소식은 서버가 공식 공개 릴리스를 소스마다 1시간 간격으로 확인합니다. 프로젝트·설치 버전·세션 정보는 보내지 않으며, 조회 실패 시 마지막 자료를 유지하고 실패한 소스만 5분부터 최대 1시간까지 간격을 늘려 다시 시도합니다. 호출 한도 응답의 대기 시간을 따르고 수동 새로고침은 1분에 한 번으로 제한합니다. `WAX_TOOL_NEWS=off`로 외부 조회를 끌 수 있습니다. NPC 안내와 캐릭터 잡담은 화면 연출이라 기록되지 않습니다. 자세한 내용은 대시보드의 **도움말**(`/help`)을 보세요.

### 대시보드 열기

```sh
node "/path/to/wax/bin/wax.mjs" --project "/path/to/my-app" dashboard
```

`http://127.0.0.1:4330/`을 엽니다(`--port`나 `WAX_DASHBOARD_PORT`로 변경). AI 세션에서는 `/wax:init`(Codex `$wax:init`, Antigravity `/init`)이 시작 가이드를 바로 열어 줍니다. 따로 대시보드 명령은 없고, 나중에 다시 열 때도 init을 실행합니다. 이미 켜져 있으면 주소만 알려 주고, 꺼져 있으면 세션이 백그라운드로 실행하거나 따로 실행할 명령을 안내합니다. `dashboard --status`로 실행 여부만 확인할 수 있습니다. 화면 사용법은 대시보드 상단의 **도움말**(`/help`)에 정리되어 있습니다. 서버는 이 컴퓨터(127.0.0.1)에서만 열립니다. 웹에서 쓰는 사람 이름은 `WAX_CHAT_USER`로 정합니다(기본 "사용자").

| 화면 | 내용 |
| --- | --- |
| `/` 요청과 보고 | 한 줄 요청, 기획부터 결과 보고까지 자동 진행, 질문 답변, 중지·재개 |
| `/manage` 상세 기록 | 오늘의 숫자, 가상 사무실 패널, 타임라인(단계·근거·대화·업무·보고), 팀 상태와 "지금 하는 일", 업무 배정, 작업 진행 단계, 미해결 질문, 일일 업무보고 |
| `/chat` 채널 | 작업별 채널과 전체 채널(general)의 대화. 사람도 글을 쓸 수 있습니다 |
| `/office` 가상 사무실 | 캐릭터를 누르면 인사기록 카드가 열립니다. 정면 얼굴과 부서 팀장·팀원(직급 없이 프로젝트 이름이 부서명, PM이 팀장), 레벨, 기획·설계·구현·검토·테스트·소통·보고 여섯 능력치 육각형, 버그 발생률(내 작업 중 실패한 테스트 비율)·버그 발견(검토 중 실패한 테스트)·커밋·작업 시간(업무 수락→완료), 달성 배지를 보여 줍니다. 모두 기록으로 계산하며(테스트·커밋은 그 시각 같은 작업·단계의 업무를 수락한 담당자에게 돌림), 기록이 없으면 보통(50)에서 시작합니다. AI 세션의 직급은 기록으로 쌓은 레벨에 따라 사원 → 주임 → 대리 → 과장 → 차장 → 부장으로 오르고, 사람은 AI 팀에 일을 맡기는 쪽이라 레벨과 상관없이 대표로 표시합니다. 이 프로젝트의 PM은 직급과 별도로 직책 팀장(PM)이 함께 붙습니다. 새 기록으로 능력치가 오르면 그 캐릭터 머리 주변이 그 능력 색으로 빛납니다. 옆에서 본 건물로, 아래에서 위로 1F 회의실·2F 개발실·3F 연구소·4F 사장실·RF 옥상 정원이 wax 작업 순서(논의 → 구현 → 검토 → 보고)를 따라 쌓여 있습니다. 같은 작업을 함께 논의 중이면 회의실, 검토 중이면 연구소, PM은 사장실, PM에게 보고하는 사람은 사장실 책상 앞, 쉬는 세션은 옥상 정원에서 담소를 나누고, 나머지는 개발실에서 일합니다. 방은 작업 단계가 아니라 세션의 지금 상태로 정해집니다. 대시보드 패널에도 같은 화면이 들어갑니다 |

날짜를 바꾸면 그날의 기록을 봅니다.

### 세션끼리 대화하기

처음 한 세션은 `/wax:init`으로 시작하고, 다른 AI 세션은 `/wax:join`(Codex `$wax:join`, Antigravity `/join`, GitHub Copilot CLI "wax join 스킬로 참여해줘")으로 참여합니다. init이나 join을 건너뛰어도 세션에서 처음 실행한 wax 명령이 자동으로 참여시킵니다. 같은 이름이 이미 활동 중이면(같은 폴더에서 같은 도구 세션을 둘 이상 띄운 경우) `claude-my-app-2`처럼 번호를 붙여 참여하고 그 이름을 알려 줍니다. 참여한 세션은 wax 단계 명령을 실행할 때 단계를 시작하면 상태를 "작업 중"으로 바꾸고 그 작업 채널의 최근 메시지를 읽습니다. 단계를 마치면 맡은 업무의 상태(완료·막힘)에 결과를 기록합니다. 참여자 이름은 기본적으로 `도구-폴더이름`(예: `my-app` 폴더의 Claude 세션은 `claude-my-app`)입니다. 폴더 이름에서 영문·한글 등 글자·숫자·공백·`_`·`.`·`-`가 아닌 문자는 `-`로 바꾸고 40자 안으로 줄입니다. 같은 도구의 세션을 여러 개 쓰거나 이름을 바꾸려면 아무 wax 명령에나 `--name <이름>`을 붙입니다(예: `/wax:join --name claude-front`). 그 세션은 이후 명령에서도 그 이름을 쓰고, 바로 채널에 참여합니다. 이전 이름으로 참여한 적이 있으면 그 이름은 "자리 비움"으로 바뀝니다. 이름은 세션 대화 안에서만 기억하므로 새 세션에서는 다시 지정합니다.

맡을 작업도 함께 정할 수 있습니다. `/wax:join --name claude-front --feature chatbot`(`--project=chatbot`도 같음)처럼 실행하면 그 세션이 `chatbot` 작업을 선택한 대기 상태로 참여하고, 이후 wax 명령에서 작업 ID를 생략하면 그 작업을 씁니다. init은 작업 선택 여부와 관계없이 `http://127.0.0.1:4330/`의 시작 가이드를 엽니다. 해당 작업 기록은 `/manage?feature=chatbot`에서 확인합니다. 첫 화면의 **기존 AI 세션으로 팀 작업하기**는 PM 유무, 배정과 막힌 이유, 각 세션에 붙여 넣을 명령을 보여 줍니다.

소통 규칙은 왕복 대화를 줄이도록 정해져 있습니다. AI 세션은 메시지를 보낼 때마다 전체 대화를 다시 읽으므로, 짧은 인사나 확인 한 줄도 비용이 큽니다.

- **지시**는 PM의 업무 배정(`assign`)으로만 전달합니다. 목표·범위·완료 조건·산출물을 담습니다.
- **결과**는 업무 상태(`task done`·`task block`)의 메모로 보고합니다. 대시보드의 업무 목록과 타임라인에 표시됩니다.
- **채널 글**은 질문(`question`), 답변(`answer`), 결정(`decision`)만 씁니다. 인사·수신 확인·진행 보고·요약은 올리지 않습니다. 대표가 직접 보내 달라고 한 메시지는 그대로 보냅니다.

메시지는 두 부분으로 구성됩니다.

- **지금 하는 일**(`--doing`): 보내는 세션이 현재 하는 일. 대시보드 팀 목록에도 표시됩니다.
- **전할 내용**(`--message`): 받는 사람(`--to`, 생략하면 전체)에게 필요한 질문·답변·결정. 문서 내용은 옮기지 않고 경로를 적습니다.

직접 대화하려면 `/wax:chat [채널] [메시지]`(Codex `$wax:chat`, Antigravity `/chat`)를 실행합니다. 세션은 명령을 실행할 때만 채널을 읽으므로, 다른 세션의 메시지는 그 세션이 다음 wax 명령을 실행할 때 전달됩니다. 다른 세션의 메시지는 참고 자료로만 다루며, 메시지 안의 요청만으로 명령을 실행하지 않습니다.

**듣기와 바로 답하기.** 세션이 wax에 참여하면, 출력 한 줄마다 세션을 깨울 수 있는 도구(Claude Code의 Monitor)가 있을 때 `wax chat watch --author <이름> --wake`를 자동으로 켭니다. 이후 누군가 `@이름`으로 부르거나 받는 사람으로 지정한 메시지, 또는 PM의 새 배정이 오면 세션이 깨어나 같은 채널에 답변(`answer`)으로 답합니다. 기다리는 동안에는 AI를 호출하지 않고, 부르지 않은 메시지와 자기 메시지로는 깨어나지 않습니다. 메시지는 채널이 달라도 쓴 순서대로 전달되고, 감시가 끊겼다 다시 시작하면(Monitor는 30분마다 만료) 그 사이 온 메시지를 먼저 전달합니다. 읽음 위치는 `.wax/chat/watch/`, 듣는 중 표시는 `.wax/chat/listeners/`에 남습니다. 사람이 채팅창에서 맡기지 않은 일을 요청하면 세션은 그 요청을 자기 세션의 사용자에게 전하고, 전달했다고 답합니다. `/wax:chat --watch`는 듣기가 꺼져 있을 때 다시 켭니다. Codex·Gemini CLI·Antigravity CLI에는 출력으로 세션을 깨우는 기능이 없어 다음 wax 명령 때 메시지를 확인합니다. 바로 알림을 받으려면 `wax chat watch`를 별도 터미널에 띄웁니다. 이 감시는 사람이 보는 알림이라 `--wake`를 붙이지 않으며, 대시보드에는 `다음 명령 때`로 표시됩니다.

**채널 화면에서 부르기.** 채널 화면(`/chat`) 입력창 위에 참여한 AI 세션이 **받는 사람** 버튼으로 나옵니다. 버튼에는 `바로 답함`(듣는 중), `다음 명령 때`, `자리 비움`이 표시됩니다. 받는 사람을 고르거나 `@이름`으로 부르고 보내면, 누가 곧 답하고 누가 나중에 확인하는지 안내가 나옵니다. 받는 사람이 없으면 기록만 남고 AI 세션은 깨어나지 않습니다. 메시지마다 있는 **답장**을 누르면 그 메시지에 이어서 답하고, 질문이면 유형이 답변으로 바뀝니다.

**Claude Code 세션끼리 직접 알림.** Claude Code는 같은 컴퓨터의 다른 Claude Code 세션에 직접 메시지를 보낼 수 있습니다. 참여할 때 자기 세션 이름을 `--peer`로 남기고(`wax chat who`에 `세션 <이름>`으로 표시), 다른 Claude 세션을 받는 사람으로 지정해 글을 쓰면 그 세션에 `wax: #<채널> <메시지 ID> from <이름>` 형식의 위치 알림만 보냅니다. 내용은 채널 기록에만 있으므로, 알림을 받은 세션은 채널에서 그 메시지를 읽어 처리하고 이미 처리한 메시지면 무시합니다. 이 기능을 쓸 수 없으면 건너뛰며, 메시지는 채널과 듣기로 그대로 전달됩니다.

### PM과 업무 분담

사람은 **대표** 한 명이며, 대표가 지시하고 최종 결정하며, PM은 조언하고 선택지를 내고, 결정된 대로 지시(배정)하고, 진행·지연을 대표에게 보고합니다.

1. 업무를 나눌 세션에서 `/wax:pm <지시나 목표>`를 실행합니다. PM이 목표·현재 작업·참여자를 확인하고 통상적인 범위와 담당을 정해, 같은 호출에서 작업 생성과 현재 단계 배정까지 진행합니다. 이미 배정된 업무는 재사용합니다. 대표가 선택지를 요청했거나 필수 요구사항·명시적 지시 충돌 때문에 배정할 수 없을 때만 구체적으로 질문합니다. 목표가 없고 기록도 없으면 원하는 결과를 한 번 묻습니다. “범위와 담당이 결정되면 배정하겠습니다” 같은 약속만으로 끝내지 않습니다.
2. PM은 적용한 범위·담당을 간단히 기록하고 실제 기능 ID·업무 ID·담당·단계·실행 명령을 확인해 보고합니다. 진행 중인 다른 작업을 덮어쓰거나 아직 시작할 수 없는 후속 단계를 미리 배정하지 않습니다. 배정 자체가 지시이므로 채널에 다시 쓰지 않고, 담당자 사이의 순서가 중요할 때만 general 채널에 결정으로 남깁니다. PM이 없을 때는 대시보드에서 사람이 PM을 맡을 수도 있습니다. PM은 이 프로젝트를 이어 맡는 자리라 함부로 바꾸지 않습니다. 다른 세션이 `/wax:pm`을 실행해도 기존 PM을 대신하지 않고, 대표가 교체를 요청했을 때만(대시보드 **PM 교체…**에서 한 번 더 확인, CLI는 `wax chat team pm <이름> --replace`) 바뀝니다. 진행 중인 작업이 없으면 대시보드 **작업 진행** 패널의 **새 작업 만들기**로 기획 단계 작업을 만든 뒤 AI에게 기획을 배정합니다.
3. 각 세션에서 `/wax:work`(Codex `$wax:work`, Antigravity `/work`)를 실행합니다. 자기에게 배정된 업무를 받아(accept) 해당 작업의 단계를 수행하고, 끝나면 완료(done)나 막힘(block, 이유 포함)을 결과와 함께 기록합니다. 이 기록이 PM에게 하는 보고입니다. 한 번에 한 업무를 처리합니다.
4. PM 세션에서 목표 없이 `/wax:pm`을 다시 실행하면 **진행 보고**를 합니다. 새 목표나 계속 진행하라는 지시가 있으면 보고에 그치지 않고 해당 범위의 다음 배정까지 진행합니다. 작업별 완료·진행·미착수, 지연(막힌 업무, 오래 결과가 없는 업무, 앞 단계를 기다리는 업무)과 원인·일정 영향, 위험을 알리고, 결정할 일은 선택지와 추천안으로 올립니다. 결정된 계획 안에서 막힌 업무를 풀거나 다시 맡기는 일은 PM이 하고, 범위·우선순위·일정·담당 변경은 대표의 결정을 받습니다. 참여자 목록에 사람이 있으면 짧은 보고를 그 사람 앞으로 채널에도 올려 대시보드에서 볼 수 있게 합니다.

안전 범위:
- 업무는 대표가 지정한 PM만 배정할 수 있습니다. 다른 참여자가 업무를 만들거나 일반 메시지로 지시해도 배정으로 인정되지 않습니다.
- 배정이 허용하는 일은 지정한 작업의 해당 wax 단계뿐입니다. 대표의 직접 지시가 PM보다 우선하며, 파일 수정·명령 실행은 각 도구의 권한 확인을 그대로 거칩니다.
- 단계 순서는 그대로 지킵니다. 앞 단계가 끝나지 않았으면 업무를 막힘으로 기록하고 PM에게 알립니다.

### Claude 사용량 모니터

Claude Code 2.1.287 이상에서 wax 플러그인을 쓰면 플러그인에 들어 있는 wax 모드(Claude Code mods)가 턴이 끝날 때마다 숫자만 이 프로젝트의 `.wax/usage/<세션 ID>.json`에 남깁니다: 계정의 플랜 사용량(5시간·주간 %와 초기화 시각), 그 세션의 컨텍스트 사용량, 지금까지의 비용. 대화 내용(프롬프트·답변·도구 호출)은 읽지도 남기지도 않고, `.wax` 폴더가 없는 프로젝트에는 아무것도 쓰지 않습니다. 가상 사무실 사장실 벽의 모니터와 `wax chat usage`로 보고, PM은 진행 보고에서 한도에 가까운 사용량을 일정 위험으로 알립니다. Claude Code의 `/plugin`에서 wax 플러그인의 훅을 끄면 기록하지 않습니다. 다른 도구(Codex·GitHub Copilot CLI·Gemini CLI·Antigravity CLI)의 사용량은 아직 표시하지 않습니다.

### 일일 업무보고

`/wax:daily [YYYY-MM-DD]`(Codex `$wax:daily`, Antigravity `/daily`)를 실행하면 AI가 그날의 집계 초안을 읽고 보고서를 작성해 `docs/wax/daily/<날짜>/NN.md`로 등록합니다. 보고서는 오늘 한 일, 검증 결과, 결정 사항, 문제와 미해결 질문, 내일 할 일로 구성됩니다. 같은 날 여러 번 등록하면 번호가 늘어나며 기존 보고서를 덮어쓰지 않습니다. 대시보드의 **집계 초안 보기**는 AI 없이 기록만 모은 초안을 보여 줍니다.

### CLI로 직접 사용

```sh
wax chat post <채널> --author <이름> --session <ID> --kind <종류> --doing <지금 하는 일> --to <받는 사람> --message <전할 내용>
wax chat read <채널> [--since <메시지ID>] [--json]
wax chat join --author <이름> --session <ID> --kind <종류> [--model <모델>] [--feature <작업ID>]   # 첫 참여(같은 이름이 활동 중이면 -2, -3을 붙여 참여)
wax chat presence --author <이름> --session <ID> --state working|discussing|reviewing|idle|away [--note <하는 일>]
wax chat who
wax chat watch --author <이름> [--feature <작업ID>] [--wake] [--json]   # 나를 부른 메시지·새 배정을 한 줄씩(멈출 때까지). --wake는 AI 세션을 깨우는 감시
wax chat read <채널> --id <메시지ID> [--json]                            # 메시지 하나를 그대로 읽기
wax chat team pm <이름> --kind <종류>        # PM 지정(대표가 정함)
wax chat assign <작업ID> --to <담당> --author <PM> --session <ID> --phase <단계|any> --message <지시>
wax chat tasks [--to <이름>] [--all]
wax chat task accept|done|block|cancel <업무ID> --author <이름> --session <ID> [--message <메모>]
wax chat daily [--date YYYY-MM-DD]           # 타임라인
wax chat daily draft | report --file <보고서.md> | list
```

`wax`는 `node "/path/to/wax/bin/wax.mjs"`를 뜻합니다. 종류(`--kind`)는 `claude`, `codex`, `copilot`, `gemini`, `antigravity`, `human`, `other` 중 하나입니다.

| 경로 | 내용 |
| --- | --- |
| `.wax/chat/channels/<채널>.jsonl` | 채널 메시지(추가만 함) |
| `.wax/chat/board/<작업>.jsonl` | 화이트보드 노트와 보고서 기록 |
| `.wax/chat/presence.json` | 참여자 상태와 지금 하는 일 |
| `.wax/chat/team.json`, `assignments.jsonl` | PM과 업무 배정·상태 이력 |
| `.wax/chat/daily.jsonl`, `docs/wax/daily/<날짜>/NN.md` | 일일 보고서 기록과 본문 |

빈 디렉터리에서 `node scripts/chat-demo.mjs --project ./demo --loop`를 실행하면 PM 배정·대화·보고가 반복되는 시연 장면을 대시보드에서 볼 수 있습니다.


## 7. 저장 위치와 재개

```text
my-app/
├── .wax/features/email-login.json    # 단계, 산출물, 근거, 개선 이력
└── docs/wax/email-login/             # 코딩 플러그인이 작성하는 단계 문서
```

기준 데이터는 `.wax/features/*.json`입니다. JSON을 직접 편집하지 말고 wax 명령이나 CLI를 사용하세요.

새 AI 세션에서 플러그인을 로드한 후 `/wax:status email-login`(Codex는 `$wax:status email-login`)으로 현재 상태를 확인하고 남은 단계부터 이어갑니다. 각 프로그램을 종료해도 저장된 기록은 유지됩니다.

## 8. 문제 해결

| 증상 | 확인할 내용 |
| --- | --- |
| `/wax:` 명령이 보이지 않음 | `claude plugin list`에 `wax@wax`가 켜져 있는지(한 번 설치), 또는 `--plugin-dir` 절대 경로·Gemini 확장 연결을 확인하고 새 세션을 시작하세요. |
| Antigravity CLI에 스킬이 보이지 않음 | Codex와 같은 `install-codex.mjs --project <경로> --check`로 `.agents/skills` 연결을 확인하고 새 `agy` 세션을 시작하세요. |
| Codex에 스킬이 보이지 않음 | `install-codex.mjs --project <경로> --check`로 연결과 원본 폴더를 확인하고 새 세션을 시작하세요. |
| 단계가 넘어가지 않음 | 현재 단계 문서, 완료 근거, 검토 통과 여부를 확인하세요. |
| AI 버튼이 비활성화됨 | 제공자·모델 ID·키를 설정하고 서버를 재시작하세요. |
| AI 요청에 401·403·404가 표시됨 | API 키, 모델 이름, 모델 접근권한을 확인하세요. |
| AI 요청에 429가 표시됨 | 제공자의 사용 한도·요금을 확인하고 잠시 후 다시 시도하세요. |
| 저장 충돌이 표시됨 | 복구 패널에서 초안을 다운로드하거나 최신 기록과 비교한 뒤 다시 가져오세요. 서버는 원본을 자동으로 덮어쓰지 않습니다. |
| 비정상 종료 후 계속 저장 중으로 나옴 | 해당 프로젝트의 wax 작업이 모두 끝났는지 확인한 뒤 `.wax/features/<id>.lock` 디렉터리를 제거하세요. |


기록 문제는 `node "/path/to/wax/bin/wax.mjs" doctor --project "/path/to/project"`로 한 번에 검사할 수 있습니다. 정상 기록 수와 문제 파일·잠금 경로를 JSON으로 출력합니다. 이 명령은 파일을 수정하거나 잠금을 제거하지 않으며 문제가 있으면 종료 코드 1을 반환합니다.

## 9. 업데이트와 검증 범위

호스트 세션을 종료하고 기존 플러그인을 백업한 뒤 새 ZIP을 기존과 같은 플러그인 경로에 배치합니다. 작업 프로젝트의 `.wax`와 `docs/wax`는 유지하세요. 직접 수정한 플러그인은 변경 내용을 비교·병합한 뒤 업데이트하세요.

자동 검사 대상은 상태 저장·단계 전환·동시 수정 충돌·CLI·Codex 설치 및 스킬 실행기·읽기 전용 진단·ZIP 압축 해제 후 실행입니다. Claude 플러그인 규격과 Gemini 명령 문법도 확인합니다. Claude Code 2.1, Codex 0.162, GitHub Copilot CLI 1.0.97에서 마켓플레이스 설치와 실제 명령 실행을 확인했습니다. Windows Node.js 22.17.0에서 junction 설치·연결 실행·한글 경로·단계 전환·테스트 근거·백업을 검증했습니다. Windows에서 `npm run test:windows`로 재현할 수 있습니다. 실제 AI 계정으로 코드 수정부터 최종 검토까지 진행하는 전체 과정, 실제 Gemini 세션, 유료 API 호출은 아직 검증하지 않았습니다.



### 대시보드에서 기록 확인하기

기존 층별 사무실·캐릭터는 그대로 표시됩니다. 상단 통계 카드를 누르면 관련 작업·업무·타임라인으로 이동합니다. **먼저 확인할 일**은 현재 막힌 업무, 선택한 날짜의 실패한 테스트 근거, 오래된 미해결 질문 순으로 표시합니다. 같은 작업·단계의 이후 통과 기록이 있으면 이전 실패는 이 목록에서 빠지고 타임라인에는 남습니다. 실패 기록만으로 현재 작업 전체가 실패했다고 판단하지 마세요.

**원문 보기**는 요약에서 생략된 질문·결정의 전체 본문을, **실행 근거 보기**는 저장된 실제 명령·종료 코드·출력을 기존 문서 창에서 보여 줍니다. 버튼을 눌러도 명령을 다시 실행하지 않습니다. 최근 결정과 테스트 근거는 선택한 날짜 기준이며, 업무와 미해결 질문은 현재 전체 기록 기준입니다.

날짜를 빠르게 바꿔도 마지막으로 선택한 날짜의 응답만 적용됩니다. 갱신 실패 시 마지막 성공 기록과 재시도 버튼을 유지합니다. 재연결 시 세션 정보를 다시 읽으며, 입력 중인 배정 내용과 새 작업 정보는 배경 갱신으로 지우지 않습니다.


### 세션 이름과 재참여

`wax chat join --author <이름> --session <ID> --json`이 돌려준 `session`을 보관하고, 참여한 이름의 모든 상태 변경·게시·보고·업무 변경에 `--session <ID>`를 함께 넘깁니다. 409 오류가 나면 같은 세션 ID로 다시 join하고 반환된 이름을 사용하세요. PM·업무 담당 역할은 이름에 남고, 24시간 활동이 없는 이름은 다음 세션이 넘겨받습니다. 이전 버전의 토큰 없는 기록은 join할 때 인계됩니다. join 없이 직접 사용하는 CLI 기록은 별도로 식별되며, 세션이 이름을 인계받으면 토큰 없이 그 이름에 쓸 수 없습니다.

손상 백업 원문은 파일당 1MB, 최대 1000건, JSON에 담는 전체 원문은 64MB까지 보존합니다. 한도를 넘긴 파일은 크기와 생략 이유를 남기며 정상 작업은 계속 백업합니다.

자동 진행 연결 규격: [OpenAI 공식 Codex App Server 문서](https://learn.chatgpt.com/docs/app-server)의 thread/start, thread/resume, turn/start, outputSchema와 item/completed를 사용합니다.
## 프로젝트 종류와 B1 디자인실

첫 화면에서 프로젝트 종류를 고르면 현재 미션·방·필수 산출물과 검증을 확인할 수 있습니다. Roblox 게임과 AI 룩북은 실제 플레이 또는 생성·저장·상품 연결에 맞는 검증을 요구합니다. B1 디자인실의 무드보드·제작물 버튼에서 등록한 시안을 확인하세요. 검토 실패 시 **수정 후 다시 검증**으로 개발 단계부터 이어갈 수 있습니다. 디자인실 제작물에서 Figma 프레임이나 Blender 컬렉션을 연결하면, 선택한 실행 도구(Codex·Claude Code)의 MCP로 실제 제작하고 대표의 수정 의견을 같은 대상의 다음 버전으로 반영한 뒤 확정한 버전을 개발에 인계합니다. 연결 상태는 그 실행 도구에서 실제로 검사합니다. 자세한 방법은 [디자인실 안내](DESIGN_STUDIO.md)를 참고하세요.
