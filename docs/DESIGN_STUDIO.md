# B1 디자인실과 프로젝트별 검증

대시보드 첫 화면의 **무엇을 만드나요?**에서 Roblox 게임·쇼핑몰 AI 룩북·일반 프로젝트를 선택합니다. 기본값은 요청 내용에서 자동 확인입니다. 새 요청에 선택한 종류를 고정하고, 현재 미션·방·필수 검증을 표시합니다. 종류를 잘못 고르면 새 요청에서 바꿀 수 있습니다. 기존 기록은 종류를 소급 변경하지 않습니다.

1F 회의실은 목표·실행 환경·작은 범위·완료 기준을 정합니다. B1 디자인실은 시안을 만들고 개발에 전달합니다. 2F 개발실은 작은 흐름을 연결하고, 3F 연구소는 실제 실행·화면을 검토하며, 4F 사장실은 결과와 남은 일을 보고합니다. 설계 중인 작업의 활동 세션은 B1에 표시됩니다. 입구와 기존 층 번호는 유지합니다.

디자인실의 무드보드 또는 **디자인실 제작물** 버튼에서 등록한 시안과 현재 작업을 확인할 수 있습니다. 시안 이미지를 표시하고, HTML은 스크립트·폼·외부 통신이 차단된 샌드박스에서 미리 봅니다. 상호작용 검증은 실제 대상 앱에서 수행해야 합니다. Blender·Studio 파일은 내려받아 해당 도구에서 확인합니다. 등록한 프로젝트 내부의 20 MiB 이하 파일만 제공합니다.

디자인실·회의실·개발실·연구소의 음료 코너는 같은 구성입니다. 수납장 위에 생수대·종이컵·커피머신을 놓습니다. 디자인실 작업대 3자리와 개발실 자유석 5자리는 회의실 자유석과 같은 접이식 의자 사용 흐름을 따릅니다. 회의실 의자 더미에서 가져와 앉고, 잠깐 서성일 때는 자리에 남기며, 다른 작업 자리로 떠날 때 반납합니다.

## 작은 결과부터 검증

| 종류 | 설계 산출물 | 구현 검증 | 검토 검증 |
| --- | --- | --- | --- |
| Roblox | 동선·조작·보상 시안 또는 블록아웃 | Studio에서 작은 게임 루프 실행 | 플레이 흐름, 조작·카메라·충돌·화면 |
| AI 룩북 | 업로드·대기·실패·편집 화면 시안 | 실제 생성부터 자체 저장까지 연동 | 생성·저장·재접속, 상품 표현 비교, 편집·상품 링크·모바일 |

SM 모드는 새 시안 제작을 의무화하지 않으며, 유지보수 범위에서 실행·회귀 검증을 수행합니다. 일반 프로젝트는 기존 검증 규칙과 저장소 관례를 따릅니다. Roblox의 멀티플레이 기능은 여러 클라이언트로 확인하고, 룩북은 생성 작업 ID를 보존하여 재접속 시 중복 요청을 방지하도록 안내합니다.

Figma는 화면 설계, FASHN 같은 API는 착용 이미지 제작, Blender는 필요한 3D 모델, Midjourney 등은 배경·소품 제작에 활용합니다. WAX가 이 도구를 설치하거나 자동 연결하지는 않습니다. 담당 AI는 실제 연결·인증·실행 방법을 확인하고 사용할 수 없는 도구를 연결됐다고 보고하면 안 됩니다.

## 근거 기록

터미널 작업은 `start ... --type roblox` 또는 `--type lookbook`으로 종류를 지정할 수 있습니다. 생략하면 제목·설명에서 확인합니다. `status`와 `prompt`에 현재 필수 항목 ID·종류가 나옵니다.

```sh
wax test <id> --revision <revision> --verification runtime --checks play-loop -- <실제 검사 프로그램> <인수>
wax complete implement <id> --revision <최신 revision> --evidence <결과> --proofs <근거 ID> --checks-file <checks.json>
```

`checks.json`은 다음 형식의 배열입니다. 자동 요청은 같은 배열을 AI 보고의 `checks`에 반환합니다.

```json
[{"id":"play-loop","status":"pass","detail":"실제로 확인한 시나리오·결과","artifact":"","proofIds":["현재 단계의 실제 근거 ID"]}]
```

`preview`는 프로젝트 상대 경로의 실제 시안 파일을 요구합니다. `visual`은 비교·검토 캡처와 `visual` 실행 근거를 요구합니다. `runtime`과 `integration`은 동일 항목 ID와 검증 종류로 기록한 성공 근거를 요구합니다. 실패·타임아웃·이전 단계·이전 개선 주기의 근거로 통과할 수 없습니다. 필수 시안·동작을 설명 문서나 문법·파일 존재 검사로 대신할 수 없습니다.

검토에서 `fail`을 보고하면 요청에 **수정 후 다시 검증**을 표시합니다. 클릭하면 개발 단계의 새 개선 주기를 시작하고 새 근거로 검토합니다. `unverified`는 환경·정보를 보완한 뒤 현재 단계부터 이어갑니다.

검증 종류와 시나리오는 검사 실행자가 정확하게 기록해야 합니다. WAX는 연결된 근거·종류·단계·성공 여부를 검사하며, 실행 명령의 의미나 게임의 재미·이미지의 상품 충실도를 독자적으로 판단하지 않습니다. 실제 대상 도구의 실행과 시각 검토가 필요합니다. 테스트 픽스처는 실제 Roblox 플레이나 FASHN API 호출의 증거가 아닙니다.
