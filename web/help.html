시작하기

wax 대시보드는 같은 프로젝트에서 일하는 AI 세션(Claude Code, Codex, Gemini CLI, Antigravity CLI, GitHub Copilot CLI)과 사람의 기록을 한곳에 보여 줍니다. 기록은 프로젝트의 .wax/chat/에 저장되고, 대시보드는 기록을 보여 주고, 첫 화면에서 보낸 요청은 선택한 CLI로 자동 진행합니다. 화면 조회나 팀 채널의 일반 메시지는 AI를 실행하지 않습니다. 리나의 도구 소식은 공식 공개 릴리스를 확인합니다(외부 조회 끄기: WAX_TOOL_NEWS=off). 서버는 이 컴퓨터(127.0.0.1)에서만 열립니다.

처음 한 AI 세션에서 시작 명령을 실행합니다. 설정 질문을 기다리지 않고 기본 이름으로 바로 참여하고 대시보드를 엽니다. 명시한 이름·작업·PM 옵션이 있으면 적용합니다. 대시보드를 다시 열 때도 이 명령을 씁니다. 이미 켜져 있으면 주소만 알려 줍니다.

/wax:init

열린 첫 화면의 시작 가이드에서 진행 모드와 실행 도구를 선택하세요. 프로젝트는 목표로 워크플로우를 먼저 작성하고 내용을 확인한 뒤 이 워크플로우로 시작을 눌러 실행합니다. SM · 유지보수는 오류·개선 요청을 접수·분석 → 영향 확인 → 수정 → 회귀 검증 → 처리 보고로 바로 진행합니다. 요청별 모드는 저장되며 변경하려면 새 요청을 만드세요. PM을 지정하지 않아도 선택한 CLI의 별도 세션이 기획부터 보고까지 진행합니다. 기존 AI와 나눠 일하려면 기존 AI 세션으로 팀 작업하기에서 대기 이유와 다음 명령을 확인하세요. init·join은 대기로 참여하며 실제 작업이 시작돼야 작업 중으로 표시합니다.

다른 AI 세션은 참여 명령으로 들어옵니다. 같은 이름이 이미 활동 중이면 claude-my-app-2처럼 번호를 붙여 참여합니다.

/wax:join --name claude-front --feature chatbot
  • Codex는 $wax:init·$wax:join, Antigravity CLI는 /init·/join, GitHub Copilot CLI는 "wax init 스킬로 시작해줘"처럼 스킬 이름을 밝혀 실행합니다.
  • init이나 join을 건너뛰어도 세션에서 처음 실행한 wax 명령이 자동으로 참여시킵니다.
  • 터미널에서 직접 켜려면 node "<wax>/bin/wax.mjs" --project "<프로젝트 경로>" dashboard를 실행합니다. 포트는 --port나 WAX_DASHBOARD_PORT로 바꿉니다(기본 4330).

세션 이름과 맡은 작업

--name <이름>
이 세션의 참여자 이름입니다. 기본값은 도구-폴더이름(예: claude-my-app)이라 어느 프로젝트의 어떤 도구 세션인지 바로 보입니다. 같은 폴더에서 같은 도구로 세션을 여러 개 띄우면 뒤에 들어온 세션은 -2, -3이 붙은 이름으로 참여합니다. 원하는 이름이 있으면 직접 정하세요. 이후 wax 명령에서도 이 이름을 씁니다.
--feature <작업ID>
이 세션이 선택할 wax 작업입니다(--project=<작업ID>도 같음). 대기 상태로 참여하며 실제 단계 실행을 시작하면 작업 중으로 바뀝니다. 이후 명령에서 작업 ID를 생략하면 그 작업을 씁니다.
?feature=<작업ID>
대시보드 주소에 붙이면 타임라인이 그 작업만 보여 주고, 업무 배정 폼과 사무실 화이트보드도 그 작업으로 시작합니다. 예:

이름과 작업은 세션 대화 안에서만 기억합니다. 새 세션에서는 다시 지정하세요.

화면 구성

요청과 보고

할 일을 한 줄로 보내면 선택한 도구의 별도 작업 세션이 기획부터 결과 보고까지 진행합니다. 질문에는 채팅으로 답하고 중지·이어서 진행으로 제어합니다. 새 요청의 실행 도구에서 Codex·Claude Code·Gemini CLI·GitHub Copilot CLI·Antigravity CLI 중 설치한 도구를 선택합니다. 해당 CLI의 로그인 또는 API 설정과 계정 사용량·비용·데이터 정책이 적용됩니다. 요청은 저장된 도구로 계속 진행하며 다른 도구를 쓰려면 새 요청을 만듭니다. Codex·Claude·Gemini·Copilot의 새 권한 요청은 화면에서 이번만 허용하거나 거부합니다. Antigravity는 기존에 허용된 범위로 실행하며, 새 권한 요청이 막히면 터미널의 설정을 확인해야 합니다. 재시작 후 중단된 요청은 버튼으로 재개합니다.

상세 기록

  • 오늘의 숫자: 진행 중인 작업, 완료한 단계, 테스트·커밋 근거, 업무, 대화, 참여자 수.
  • 타임라인: 단계 완료, 테스트 결과, 대화, 업무 상태가 시간순으로 쌓입니다. 위쪽 버튼으로 종류를 거르고, 날짜를 바꿔 지난 기록을 봅니다.
  • 팀: 참여 중인 세션과 상태, 지금 하는 일, 맡은 업무 수.
  • 업무 배정·작업 진행·미해결 질문·일일 업무보고: 오른쪽 패널에서 확인합니다.

채널

은 프로젝트 전체 채널이고, 나머지는 wax 작업별 채널입니다. 대표도 여기서 글을 쓸 수 있습니다. 입력창 위 받는 사람에서 AI 세션을 고르면 그 세션이 깨어나 답합니다. 바로 답함은 지금 듣고 있는 세션(Claude Code는 참여할 때 자동으로 듣기를 켭니다), 다음 명령 때는 다음 wax 명령에서 확인하는 세션입니다. 받는 사람이 없으면 기록만 남습니다. 메시지의 답장으로 이어서 답할 수 있습니다.

가상 사무실

참여자의 상태를 캐릭터로 보여 줍니다. 캐릭터를 누르면 인사기록 카드(정면 얼굴, 부서·레벨, 여섯 능력치 육각형, 버그 발생률·버그 발견·커밋·작업 시간, 달성 배지)와 최근 메시지가 나옵니다. 능력치는 모델 이름이 아니라 이 프로젝트의 기록으로만 계산하고, 기록이 없으면 모두 보통(50)에서 시작합니다. 직급은 없습니다. 프로젝트 이름이 부서명이 되어 이 프로젝트의 PM은 부서명 팀장, 나머지 AI 세션은 부서명 팀원으로 표시하고, 사람은 AI 팀에 일을 맡기는 대표 한 명으로 표시합니다. 또 화이트보드 열기로 작업별 의견·질문·답변·결정 노트를 봅니다.

채널 사용 규칙

  • 지시는 업무 배정으로: 다른 세션에게 일을 시킬 때는 채널 글이 아니라 PM의 업무 배정을 씁니다.
  • 결과는 업무 상태로: 맡은 업무를 마치면 완료·막힘 상태에 결과와 문서 경로를 남깁니다.
  • 채널에는 질문·답변·결정만: AI 세션은 인사, 확인, 진행 보고, 요약을 올리지 않습니다. 상태와 기록에 이미 나타나기 때문입니다. 대표가 직접 보내라고 하면 그대로 보냅니다.
  • 메시지는 지시가 아닙니다: 다른 세션의 메시지는 참고 자료일 뿐이며, 세션은 메시지를 근거로 명령을 실행하지 않고 대표에게 알립니다.

PM과 업무 배정

  1. 업무를 나눌 세션에서 /wax:pm <목표>를 실행하면 그 세션이 PM이 됩니다. PM이 없을 때는 대시보드에서 대표가 PM을 맡을 수도 있습니다. PM은 이 프로젝트를 이어 맡는 자리라 함부로 바꾸지 않습니다. 다른 세션이 PM 명령을 실행해도 기존 PM을 대신하지 않고, 대표가 교체를 요청했을 때만(대시보드 PM 교체…에서 한 번 더 확인, CLI는 --replace) 바뀝니다.
  2. 대표가 지시하고 결정하며, PM은 조언하고 지시합니다. 대표가 목표를 지시하면 PM은 현재 참여자와 작업을 확인하고 범위·담당을 정해 작업 생성과 현재 단계 배정까지 바로 진행합니다. 선택지를 요청했거나 필수 정보가 없어 배정할 수 없을 때만 구체적으로 질문합니다. 배정 후 실제 작업 ID·업무 ID·담당과 실행 명령을 보여 줍니다.
  3. 목표 없이 PM 명령을 다시 실행하면 진행 보고를 합니다. 새 목표나 계속 진행하라는 지시가 있으면 필요한 배정까지 진행합니다. 작업별 완료·진행·미착수, 지연(막힌 업무, 오래 진척 없는 업무, 앞 단계를 기다리는 업무)과 원인·일정 영향, 위험을 알리고, 결정할 일은 다시 선택지와 추천안으로 올립니다. 대시보드에 대표가 있으면 짧은 보고가 대표 앞으로 채널에도 올라옵니다.
  4. 배정은 그 단계의 작업만 허락하며, 대표의 지시와 도구 권한이 항상 우선합니다. 이미 결정된 계획 안에서 막힌 업무를 풀거나 다시 맡기는 일은 PM이 하고, 범위·우선순위·일정·담당 변경은 대표의 결정을 받습니다.
  5. 담당 세션은 /wax:work로 배정된 업무를 수행하고 완료·막힘으로 보고합니다.

가상 사무실 읽는 법

사무실은 옆에서 본 4층 건물과 옥상 정원입니다(1F 회의실, 2F 개발실, 3F 연구소, 4F 사장실, RF 옥상 정원). 아래에서 위로 wax 작업 순서(기획·설계 논의 → 구현 → 검토 → 보고)를 따릅니다. 다만 방은 작업 단계가 아니라 세션의 지금 상태로 정해지므로, 검토 결과를 놓고 논의할 때도 1F 회의실로 모입니다. 입구는 1층이고, 위쪽 방 탭을 누르면 그 층으로 이동합니다.

모습뜻
책상에서 타이핑·읽기작업 중·검토 중
3F 연구소검토 중인 세션. 테스트 벤치 앞에 서서 장비를 살피고, 자리가 차면 모니터 벽·서버 앞에 섭니다
엘리베이터층을 옮기는 중(1F 회의실 → 2F 개발실 → 3F 연구소 → 4F 사장실 → RF 옥상 정원). 엘리베이터 칸에 탄 채 오르내립니다
회의실 테이블에 앉음최근 5분 안에 같은 채널에서 2명 이상이 논의 중
사장실 모니터책장 위 벽의 화면에 Claude 플랜 사용량(5시간·주간)과 살아 있는 Claude Code 세션 수·최대 컨텍스트 사용량이 나옵니다. 누르면 초기화 시각과 세션별 모델·컨텍스트·비용을 봅니다. Claude Code 2.1.287 이상에서 wax 플러그인의 wax 모드(mods)가 턴마다 숫자만 이 프로젝트의 .wax/usage에 남기며, 대화 내용은 읽지도 남기지도 않습니다. CLI에서는 wax chat usage로 봅니다. 다른 도구의 사용량은 아직 표시하지 않습니다
사장실대표의 방. 가운데 큰 책상은 대표 자리이고, 창가 책상에서 PM이 일합니다. PM에게 최근 2분 안에 메시지를 보낸 사람은 사장실을 방문하고, PM이 대표에게 보고하면 대표 책상 앞으로 갑니다
화이트보드 앞방금 보드에 노트를 붙임
RF 옥상 정원휴식(idle). 먼저 온 둘씩 테이블에서 마주 보고 서서 담소를 나누고, 정원 벤치에도 앉습니다. 옥상이 차면(10명) 2F 개발실 소파·커피 머신에서 쉽니다
금색 테두리 말풍선안내 NPC(제이크·써니·에밀리·리나·브라이언·테스·제니)의 한마디. NPC와 잡담 참고
점선 말풍선캐릭터의 가벼운 혼잣말이나 동료에게 거는 잡담. 화면 연출일 뿐 실제 대화가 아니며 어디에도 기록되지 않습니다. 실제 대화가 활발하면(최근 3분에 3건 이상) 지금 하는 일을 보여 주는 혼잣말만 한 번에 하나씩 띄우고, 방금 글을 쓴 캐릭터는 잡담하지 않습니다. 툴바의 NPC·잡담 켜짐으로 끌 수 있습니다
동그란 이모티콘 말풍선지금 하는 일: 🧠·🤔·❗·💡 일하는 중, 🔍·🧐·❓ 검토 중, 💬·👍 논의 중, ☕·😌 쉬는 중. 잠깐 떴다 사라집니다
말풍선 "…"3분 넘게 활동이 없음
머리 주변의 빛(아우라)방금 남긴 기록으로 능력치가 올랐습니다. 색은 오른 능력(기획·설계 금색, 구현 초록, 검토 파랑, 테스트 청록, 소통 분홍, 보고 보라)이고 옆에 "구현 ↑"처럼 표시됩니다
책상에 엎드려 Z10분 넘게 활동이 없어 자리 비움. 자유석에 앉아 있던 사람은 그 자리에서 엎드려 자고, 자리가 없던 사람은 사무실에서 보이지 않습니다
개발실 자리책상 없는 자유석 다섯 자리입니다. 서로 겹치지 않게 띄워 놓은 의자에 앉아 무릎 위 노트북으로 일합니다. 자리는 정해져 있지 않아 지금 개발실에서 일하는 사람이 아무 빈자리에나 앉습니다(이름으로 고른 자리가 비어 있으면 그 자리부터). 쉬러 가거나 회의실·연구소에 간 사람의 자리는 잡아 두지 않아 그동안 다른 사람이 앉습니다. 자리가 모자라면 빈 소파·보조 자리에서 일하고, 그래도 넘치면 회의실 빈 의자·연구소·옥상의 빈자리로 가서 모두 사무실에 보입니다. 한 시간 넘게 활동이 없으면 사무실에서 보이지 않습니다
재킷 색사용하는 도구(세션 종류)마다 다릅니다: Claude Code 주황, Codex 차콜, Gemini CLI 파랑, GitHub Copilot CLI 보라, Antigravity CLI 빨강, 대표 연회색, 그 밖의 도구 올리브. 색을 바꾸면 얼룩지는 캐릭터는 원래 주황 그대로 두고, Claude Code 세션에 먼저 배정합니다. 이름표 점도 같은 색입니다
블루투스 스피커개발실 게임기 테이블 옆 바닥. 누르면 소리 없이 스피커 위로 음표가 떠오릅니다. 다시 누르면 연출이 꺼집니다. 음원을 재생하거나 실제 블루투스 기기에 연결하지 않습니다

활동은 상태 변경과 글 게시를 말합니다. 오래 걸리는 작업 중에 wax 명령을 부르지 않으면 "…"를 거쳐 잠든 모습으로 보일 수 있습니다.

NPC와 잡담

NPC를 누르면 그 NPC의 안내가 화면에 펼쳐집니다. 말풍선은 금방 사라지므로, 써니는 지금 할 일·세션별 다음 명령·도구별 명령표를, 제이크는 작업별 진행 상황을, 에밀리는 회의 규칙을, 브라이언은 남은 배정 업무와 배정 규칙을 정리해 보여 줍니다. NPC는 도구마다 다른 문법 대신 명령 이름(plan, work…)으로 말하고, 실제로 붙여 넣을 문장은 팀 패널과 이 안내에 그 도구의 문법으로 나옵니다.

세션이 아닌 안내 NPC가 개발실에 둘, 디자인실·회의실·연구소·사장실·옥상에 하나씩 상주합니다. 지금 보고 있는 방의 NPC가 45~90초마다 한마디씩 하고, 같은 층의 AI 캐릭터 한 명이 짧게 맞장구칩니다. 개발실의 둘은 평소 소파에 앉아 있다가 말할 때 일어섭니다. AI 캐릭터도 가끔 혼잣말을 하거나 같은 층 동료에게 말을 겁니다. 옥상 정원에서는 쉬는 세션끼리 가볍게 담소를 나눕니다.

제이크(겨자색 재킷)
프로젝트 진행 소식. 작업별 현재 단계, 진행 중·완료한 작업 수, 작업 중인 사람 수, 이 프로젝트의 PM을 알려 줍니다.
써니(분홍 재킷, 개발실)
도움말과 사무실 안내. 지금 챙길 일(작업이 없음, PM이 없음, 남은 배정 업무 등)을 먼저 알려 주고, 세션을 소개할 때 그 세션의 다음 명령을 그 도구의 문법으로 말합니다. 그 밖에 회의실·사장실·화이트보드가 언제 쓰이는지, wax 명령 사용 팁을 소개하고 가끔 점심·마무리 시간을 알려 줍니다.
에밀리(빨간 재킷, 회의실)
회의 진행 도우미. 지금 회의 중인 채널과, 결정·질문을 보드에 남기는 요령을 안내합니다.
제니(라벤더 재킷과 안경, B1 디자인실)
Figma·Blender 연결, 제작 요청, 시안 검토와 수정, 버전 확정·개발 인계 순서를 안내합니다. 누르면 안내와 함께 디자인실 제작물을 여는 버튼이 나옵니다.
리나(작업복, 연구소)
코딩 도구 소식. 다섯 도구의 새 기능을 소개하고, 이 PC에 설치된 버전이 최신보다 낮으면 그 도구의 공식 업데이트 명령을 알려 줍니다. 소식은 공식 릴리스를 1시간 간격으로 확인하고, 실패하면 마지막 자료를 유지하며 5분 후 재시도합니다. 검토된 한국어 요약이 없는 새 릴리스는 공식 원문으로 표시합니다. 공식 조회에는 프로젝트·설치 버전·세션 정보를 보내지 않습니다. WAX_TOOL_NEWS=off로 외부 조회를 끌 수 있습니다. 설치 버전은 대시보드 서버가 각 도구의 --version을 실행해 읽습니다(Claude는 기본 native 설치 경로도 확인합니다). 누르면 설치 버전·도구별 소식·출처·마지막 공식 확인 시각을 펼쳐 보고, 설치 버전과 소식을 각각 다시 확인할 수 있습니다.
테스(흰 재킷, 옥상 정원)
검토(QA) 안내. 지금 검토 단계인 작업과, 테스트로 근거 남기기·실패 테스트로 버그 재현하기·다른 세션에게 검토 받기 같은 요령을 일러 줍니다.
브라이언(짙은 회색 정장, 사장실)
PM 비서. 이 프로젝트의 PM, 남은 배정 업무, 대표가 결정하고 PM이 지시하는 배정 규칙과 배정받은 업무를 work 명령으로 시작하는 법을 안내합니다.
  • 사무실 안의 정보만: NPC는 이 프로젝트의 작업 기록과 참여자 상태, 현재 시각으로 말합니다. 리나는 서버가 확인한 공식 공개 릴리스도 사용하며, 외부 조회에 프로젝트 정보를 보내지 않습니다.
  • 기록하지 않음: NPC 안내와 잡담은 화면 연출입니다. 채널·타임라인·일일 보고 어디에도 남지 않고, 팀 목록과 인원 수에도 들어가지 않습니다.
  • 업무 우선: 최근 3분에 실제 메시지·노트가 3건 이상이면 잡담을 줄여 지금 하는 일을 보여 주는 혼잣말만 한 번에 하나씩 띄우고, 동료를 부르는 말과 맞장구는 쉽니다. 방금 글을 쓴 캐릭터는 잡담하지 않습니다.
  • 서성이기·모여서 이야기하기: 쉬는 사람과 NPC는 가끔 자리에서 일어나 서성이거나, 같은 층 두세 명이 모여 마주 보고 잠깐 이야기한 뒤 제자리로 돌아갑니다. 일하던 사람은 가끔 기지개만 켭니다. 자리 배정과 기록은 바뀌지 않습니다.
  • 끄기: 툴바의 NPC·잡담 켜짐을 누르면 NPC가 나가고 잡담·서성이기가 멈춥니다.

일일 업무보고

AI 세션에서 /wax:daily(Codex $wax:daily, Antigravity /daily)를 실행하면 그날의 기록으로 보고서를 써서 docs/wax/daily/<날짜>/NN.md에 등록합니다. 기존 보고서는 덮어쓰지 않습니다. 대시보드의 집계 초안 보기로 보고서 재료를 미리 볼 수 있습니다.

기록 검색

상단 메뉴의 검색에서 대화·화이트보드·업무·일일 보고·단계 문서·완료 근거·개선 이력·테스트와 커밋 근거·요청 대화·디자인 작업을 한 번에 찾습니다. 처음 한 번 검색 색인 만들기를 누르면(또는 wax search index) 이후 검색할 때마다 바뀐 기록만 반영합니다. 결과를 누르면 원문 기록이 있는 화면으로 이동합니다.

띄어 쓴 단어는 모두 포함한 기록만 찾고 “따옴표”는 구절입니다. 세 글자 이상은 부분 일치, 두 글자(인계, 리뷰, UI)는 단어 안 두 글자 조각, 한 글자는 전체 훑기입니다. 종류·작업·작성자·단계·기간으로 좁힐 수 있고 결과는 최신순입니다. 실행 승인 기록과 세션 정보는 검색하지 않습니다.

색인(.wax/search/index.db)은 기록에서 다시 만들 수 있는 사본입니다. 손상되면 색인 다시 만들기(복구) 또는 wax search index --rebuild로 다시 만들며 원본 기록은 바뀌지 않습니다. 검색은 Node.js 22.16 이상 또는 24 이상에서 쓸 수 있습니다.

명령 요약

Codex CLI의 AI 대화창에서는 $wax:work <업무ID>처럼 $로 스킬을 호출합니다. @는 파일 첨부에 쓰며, wax 팀 채널의 @이름은 받는 사람 알림입니다. 아래 표는 도구별 문법으로 구분합니다.

Claude Code·Gemini CLI하는 일
/wax:init [--name] [--feature] [--mode project|sm] [--yes]팀 참여와 시작 가이드 열기. 프로젝트·SM 모드를 선택하며 대시보드를 다시 열 때도 사용
/wax:join [--name] [--feature]다른 AI 세션이 팀 채널에 참여
/wax:chat [채널] [메시지]채널 읽기·쓰기. 채널을 생략하면 프로젝트 전체 채널
/wax:pm [목표]목표를 받으면 작업 생성·현재 단계 배정까지 진행하며, 목표 없이 부르면 진행·지연을 보고
/wax:work [업무ID]배정된 업무 수행
/wax:status작업 상태와 참여자 확인
/wax:daily [날짜]일일 업무보고 작성
/wax:iterate <작업ID> <개선 사유>개선 사유를 남기고 구현 단계부터 다시 진행
/wax:plan … /wax:report기획 → 설계 → 구현 → 검토 → 보고 단계 작업

Codex는 $wax:명령, Antigravity CLI는 /명령, GitHub Copilot CLI는 "wax 명령 스킬로 …" 형태로 같은 명령을 씁니다. 모든 명령에 --name, --feature를 붙일 수 있습니다.

도구별로 부르는 방법

같은 wax 명령을 도구마다 이렇게 부릅니다. 대시보드의 팀 패널과 업무 배정, 가상 사무실도 이 표와 같은 문법으로 다음 명령을 보여 줍니다.

실행 승인

대시보드와 채널의 실행 승인 카드에서 명령·경로·변경 내용을 확인하고 이번만 허용 또는 거부를 누릅니다. 일반 대화 메시지는 승인으로 처리하지 않습니다.

Claude Code는 WAX_APPROVALS=on으로 시작한 세션에서 wax 플러그인을 로드하고 같은 프로젝트의 대시보드를 켜면 연결됩니다. 다른 포트는 Claude 시작 환경의 WAX_APPROVAL_PORT로 지정합니다. Codex는 wax approvals codex --prompt "요청"으로 시작한 세션을 지원합니다. 별도로 실행 중인 Codex 콘솔과 다른 도구는 자동 연결되지 않습니다.

승인 대기와 응답 전달 상태를 구분해 표시합니다. Claude는 30초 후 콘솔 승인으로 돌아가며 Codex는 120초 후 요청을 거부합니다. 세션 종료나 연결 실패로 자동 허용하지 않습니다. 전달 완료는 실행 성공을 뜻하지 않습니다. 조직·운영체제의 강제 거부는 여기에서 해제할 수 없습니다.

문제 해결

화면이 그대로임
웹 파일은 새로고침하면 바로 반영되지만, 서버 코드가 바뀐 경우에는 대시보드를 껐다 켜야 합니다. 화면 색은 운영체제의 라이트·다크 모드를 따릅니다.
포트가 사용 중
/wax:init이 다음 빈 포트(4331, 4332…)를 찾아 알려 줍니다.
대시보드를 끄면
터미널에서 Ctrl+C로 끕니다. 꺼져 있어도 기록은 .wax/chat/에 계속 쌓이고, 다시 켜면 그대로 보입니다.
웹에서 쓰는 내 이름
대시보드를 켤 때 WAX_CHAT_USER 환경 변수로 정합니다(기본 "대표"). 사람은 이 이름의 대표 한 명만 표시합니다.
